List Bits Security Analyst investigations.

List Bits Security Analyst investigations.

Without filter[signal_id], returns the latest investigation of each signal, filtered, sorted, and paginated. With filter[signal_id], returns every investigation of that signal, newest first. When the signal has no investigation, the first page carries meta.reason, which says why.

Parameters:

  • opts (Hash) (defaults to: {}) —

    the optional parameters

Options Hash (opts):

  • :filter_signal_id (String) —

    List every investigation of this signal, newest first. Accepts the signal ID in its V1 form, which starts with AQ, or in its longer V3 form, which starts with Aw. Investigations carry the V1 form, so their signal_id can differ from the ID you pass. Can't be combined with other filters or with sort.

  • :filter_title (String) —

    Only investigations whose signal title contains this text, case-insensitive.

  • :filter_from (String) —

    Only investigations last updated at or after this time, as RFC 3339 or milliseconds since the epoch.

  • :filter_to (String) —

    Only investigations last updated at or before this time, as RFC 3339 or milliseconds since the epoch.

  • :filter_verdict (String) —

    Only investigations with one of these verdicts: benign, suspicious, or malicious. Comma-separated values; an investigation matches any of them.

  • :filter_state (String) —

    Only investigations in one of these states: investigating or completed. Investigations reported as failed match investigating. Comma-separated values; an investigation matches any of them.

  • :filter_rule_id (String) —

    Only investigations of signals from one of these detection rule IDs. Comma-separated values; an investigation matches any of them.
